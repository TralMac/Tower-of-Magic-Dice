## 0. 一句话 & 设计支柱

**一句话**：经典魔塔的「爬层 + 钥匙门 + 资源规划」，把固定数值战斗换成**骰子对抗**，每个角色就是一套骰子，用技能树和遗物去「驯服运气」。

| 支柱 | 含义 | 落到设计上 |
|---|---|---|
| **骰子即角色** | 3d4、2d6、1d12……不同骰型 = 不同玩法 | 各角色**期望值接近（≈7）**，区别在**方差**和**操控骰子的方式** |
| **可计算的运气** | 魔塔的乐趣是「算」，骰子带来的是「赌」 | 怪物手册显示**胜率 / 期望掉血 / 最坏情况**；ATB 行动顺序**完全确定、提前可见** |
| **越打越破** | 护甲会磨损，战斗有节奏变化 | 前几次交锋拼防御，护甲碎后伤害陡增；群体怪专克护甲 |
| **每一环都能被改写** | 战斗流程每个阶段都有遗物钩子 | 统一的事件时序 + 修正顺序，保证遗物可组合、不打架 |
| **罪即玩法** | 每个角色背负一宗罪，玩法由罪而来 | 专属系统、技能树、遗物、结局都从角色的罪和故事推导 |

## 0.5 世界观与七宗罪（草案）

**魔塔**：传说世界尽头有一座魔塔，塔顶放着「命运之骰」，掷出它就能改写一段过去。魔塔只接纳罪人：被某种罪孽吞噬的人，灵魂会被铸成骰子，叫做**罪骰**。罪骰的形状就是罪的形状。塔里的怪物是历代登塔失败者的执念。

**七宗罪 = 七个角色**。先做 4 个，其余 3 个留作后续角色：

| 贪婪 | 赌徒 | 1d12 | 一颗骰子，孤注一掷，只想要最大的那个数 | ✅ 罪已定，背景待写 |

| 懒惰 / 暴食 / 色欲 | 后续角色 | 待定 | — | 待定 |

【建议】**罪之镜**：每个角色的最终首领都是自己罪的镜像，使用该角色的骰型和专属系统。这样四个角色走同一张塔，结局战也各不相同。

## 1. 核心循环（固定关卡的纯魔塔）

```
选角色(骰型) → 进入塔层 → 探索：开门/拿钥匙/捡宝石药水/遇事件
      ↑                         ↓
   商店/祭坛  ←  击败怪物 → 金币 + 经验 → 升级 → 技能点
      ↑                         ↓
   首领层 → 固定遗物奖励       特质（固定事件给予，好坏都有）
```

- **地图、怪物、道具、遗物、事件的位置全部固定**，由关卡策划手工摆放。玩家的乐趣在于**规划路线**：先开哪扇门、先打哪只怪、钥匙留给谁。
- HP 是跨战斗的核心资源（沿用魔塔「血量即货币」）；护甲每场结束后恢复满（见 2.2）。
- 唯一的随机来源是**战斗中的骰子**。关卡里不放随机掉落、随机事件，保证「同一张图，规划决定一切」。

### 1.1 固定关卡带来的设计要求【建议】

| 问题 | 方案 |
|---|---|
| **存档读档刷骰子**：固定地图下，玩家会读档重打一场烂运气的战斗 | ✅ 随机数种子写进存档：**读档后同样的操作会得到同样的骰子**，想改结果就必须改决策（换路线、换技能使用时机）。种子随每次投骰推进。另设**宽松模式**开关：开启后读档重新随机。已知局限：玩家仍可「读档看一遍骰子再读档」，种子方案挡不住，但必须改变决策才能改变结果，可以接受 |
| **一张图要适配四个角色** | ✅ 同一张塔。主路线按「裸装中位角色」设计；少量**角色专属格子**（同一位置，不同角色拿到不同的专属遗物 / 宝石），并为每个角色单独跑一遍数值验证 |
| **遗物不能三选一（那是 Roguelite 的做法）** | 遗物放在固定位置：首领掉落、隐藏房间、商店高价货；少数岔路做「二选一的门」，路线即选择 |
| **开局特质** | 改为**开局可选的挑战选项**：自愿带上负面特质，换取结算评分 / 称号（类似难度等级） |

## 2. 骰子基础规则

### 2.1 三种骰池

每个单位（玩家和怪物同规则）有三组骰：

| 骰池 | 作用 | 说明 |
|---|---|---|
| **攻击骰** | 攻击时投掷 | 角色的「本命骰」，决定角色身份 |
| **防御骰（护甲）** | 被攻击且未闪避时投掷 | 会**磨损**（见 2.2） |
| **闪避骰** | 被攻击时先投 | 通常很小（d2~d6），重甲怪可以没有 |

✅ **已定（Q2）：只有攻击骰是本命骰；防御骰另配，但沿用本命骰的「形状」；闪避骰统一用小骰（d2~d6）。**

- 为什么闪避不能用本命骰：2d6 攻击对 2d6 闪避，「A ≤ E」的概率是 55.6%，超过一半的攻击会被躲掉，战斗会拖长一倍。
- 形状沿用：多颗小骰的角色，护甲也是多颗小骰，一颗一颗地掉；单颗大骰的角色，护甲也是单颗大骰，要么挡住，要么挡不住。

| 角色 | 本命骰（攻击） | 防御骰（同形状） |
|---|---|---|
| 铁卫 | 3d4（三颗小骰） | 3d4 |
| 战士 | 2d6（两颗中骰） | d6+d4 |
| 赌徒 | 1d12（一颗大骰） | 1d8 |
| 咒术师 | d8+d4（一大一小） | d6+d2 |

### 2.2 护甲等级 & 磨损

把「2d6 防御失败 → 1d6+1d4」规则化：

- **护甲等级 = 所有防御骰的面数之和**。2d6 = 12 级，1d6+1d4 = 10 级。
- **每降 1 级：面数最小的那颗骰子 −1 面**（网页游戏可以有 d5、d3 这种实体不存在的骰子）。
- 骰子降到 d1 时**碎裂移除**。

```
2d6 → d6+d5 → d6+d4 → d6+d3 → d6+d2 → d6 → d5 → d4 → d3 → d2 → 无甲
 12     11      10      9       8      6    5    4    3    2
```

- 防御成功 −1 级，防御失败 −2 级。
- ✅ **已定：护甲只在单场战斗内磨损，战斗结束后恢复满**。怪物同理（不会出现「上次打残的怪」）。
- 【建议】同一套规则也用来**成长**：防御宝石 = 护甲上限 +1 级（给最小的骰子 +1 面）；攻击宝石同理。成长和磨损共用一套「面数阶梯」，玩家只需要学一次。

### 2.3 修正顺序（防止遗物互相打架）

每次投骰按以下顺序结算，**同一层内先攻击方、后防御方，同一方按获得顺序**：

1. **投骰前**：改骰池（加骰、换骰、「减少对面骰子」）
2. **投骰**
3. **骰面操作**：重投、锁定、翻面、把某颗骰改成指定值
4. **加减值**：技能 +1、特质 ±1、遗物加值
5. **乘算**：暴击 ×2 等
6. **下限截断**：最终点数不低于 0

## 3. 战斗流程（状态机）

```
[战斗开场] ─→ [ATB 推进] ─→ [行动者攻击声明] ─→ [攻击投骰] ─→ [闪避判定]
                  ↑                                              │ 失败
                  │                                              ↓
           [战斗结束检查] ←── [受到伤害] ←──────────────── [防御判定]
                  │ 一方 HP ≤ 0
                  ↓
             [战斗结算]
```

| # | 阶段 | 做什么 | 遗物钩子（先攻击方 → 后防御方） |
|---|---|---|---|
| 1 | 战斗开场 | 初始化护甲、群体层数、行动条起始值 | `onBattleStart` |
| 2 | ATB 推进 | 推进行动条直到有人满条，决定行动者（见 3.1） | `onGaugeFull` / `onActionStart` |
| 3 | 攻击声明 | 确定段数（群体）、目标 | `onAttackDeclare` |
| 4 | 攻击投骰 | 按 2.3 结算攻击点数 **A** | `onAttackRoll` |
| 5 | 闪避判定 | 防御方投闪避 **E**；若 **A ≤ E** → 闪避，本段结束 | `onDodgeCheck` / `onDodged` |
| 6 | 防御判定 | 防御方投护甲 **D**；成功/失败，护甲 −1/−2 | `onDefenseCheck` / `onArmorBreak` |
| 7 | 受到伤害 | 扣 HP = max(0, A − D) | `onDamageTaken` / `onDamageDealt` |
| 8 | 结束检查 | 有一方 HP ≤ 0 → 结算；否则行动者行动条 −100，回到 2 | `onActionEnd` |
| 9 | 战斗结算 | 经验、金币、掉落、特质触发；**护甲恢复满** | `onBattleEnd` / `onKill` |

### 3.1 ATB 行动条 ✅ 已定

**规则**

- 每个单位有一条行动条，**满值 100**，战斗开场为 0（技能 / 遗物可以给起始值，即「先手」）。
- 时间以「刻」推进，每刻行动条 **+速度**。
- 行动条 ≥ 100 → 该单位行动（一次完整攻击，含群体多段），行动后 **−100，保留溢出**。
- 同一刻多个单位满条：**溢出多者先 → 速度高者先 → 玩家优先**。
- 速度取值建议在 **8~14** 区间（平均 10）。速度比就是行动次数比：速度 14 对速度 10，我方每行动 5 次，对方行动 7 次，其中 2 次是连动。

**示例**（模拟器实际输出）：战士（速 10）vs 蝙蝠群（速 14），前 12 次行动：

```
敌 我 敌 我 敌 敌 我 敌 我 敌 敌 我
```

**为什么 ATB 不会破坏「可计算」**

- 速度和行动条**没有随机成分**，所以整场的行动顺序在开战前就能完全算出。
- 【建议】战斗界面顶部常驻**行动顺序条**（未来 8 次行动的头像队列，类似 FF10 的 CTB），怪物手册里也显示「敌我行动比」。
- 【建议】表现上行动条实时流动（满足「即时」感），但采用**等待模式**：玩家的决策窗口打开时，所有行动条暂停。

**ATB 带来的新设计空间**

| 类型 | 例子 |
|---|---|
| 推条 / 拉条 | 「震慑」：命中时目标行动条 −30；「疾风」：闪避成功后自身行动条 +20 |
| 先手 | 「伏击」：开场行动条 +50；蝙蝠这类高速怪开场就能连动 |
| 速度增减 | 特质「迟钝」速度 −2；咒术师的「减速诅咒」 |
| 持续时间 | 所有「持续 N 回合」统一改为「持续到**挂载者**的第 N 次行动结束」 |

> ⚠️ 模拟显示**速度在 ATB 下等于伤害乘数**：赌徒速度 12 时行动次数是速度 9 单位的约 1.3 倍。速度成长必须稀缺且昂贵（例如全塔只有 2~3 个速度宝石）。

### 3.2 玩家在战斗中的决策点【建议】

默认自动结算（可以 2×/4× 加速），只在两个时机弹出决策窗口（窗口打开时行动条暂停）：

- **自己投出攻击骰后**：要不要重投 / +1 / 爆骰。
- **敌人投出攻击骰后、自己判定闪避和防御前**：要不要削对面骰子、用防御技能。

不用技能就自动继续，大部分战斗依然很快，关键的一投由玩家掌控。

✅ **撤退（Q6）**：只能在决策窗口中发起，首领战不能撤退。除了已经损失的 HP，没有额外惩罚；怪物的 HP 和护甲恢复满，随机种子继续往前走，下次再打骰子不同。相当于「花血换一次重投」。如果测试中出现「打两下不行就跑」的滥用，再加「撤退扣 10% 金币」。

## 4. 判定公式（单段攻击）

```
A = 攻击骰结果 + 修正                     （特质、技能、遗物）
E = 闪避骰结果 + 修正
if A ≤ E:            → 闪避成功：无伤害，护甲不变（Q8）
D = 防御骰结果 + 修正
if A > D:            → 防御失败：HP −(A − D)，护甲 −2 级
else:                → 防御成功：无伤害，护甲 −1 级
```

- ✅ **Q7**：所有修正后点数截断为 0。0 点攻击必定被闪避（0 ≤ 任何 E，包括没有闪避骰时的 E = 0），显示为「无力的一击」。
- ✅ **Q8**：闪避成功**不磨损护甲**。三档反馈：闪避 = 什么都不丢；防御成功 = 掉 1 级护甲；防御失败 = 掉血并掉 2 级护甲。

**例**：战士（攻 2d6）打骷髅兵（闪 1d2，防 2d6）
1. 战士投出 9。骷髅兵闪避投出 2 → 9 > 2，闪避失败。
2. 骷髅兵防御投出 6 → 9 > 6，防御失败：骷髅兵 −3 HP，护甲 2d6 → d6+d4。
3. 下一次骷髅兵的防御期望从 7 降到 6，护甲越打越薄。

## 5. 群体机制

- 群体 N：每次攻击变成 **1 + N 段**，每一段**独立**投攻击骰，独立走闪避 / 防御 / 伤害。
- **群体对护甲是克星**：每一段都会磨掉 1~2 级护甲，所以群体怪单段骰子必须小（1d4~1d6），否则会碾压高护甲角色。
- ATB 下群体怪的总威胁 ≈ **段数 × 速度**。高速 + 群体（如蝙蝠群）要压低单段骰子或 HP。
- 【建议·可选】**群体随血量瓦解**：群体 N 的怪每损失 1/(N+1) 的最大 HP，群体层数 −1。表现为「打散一群哥布林」，也让玩家的爆发更有价值。
- 【建议】给玩家留应对手段：群攻 / 溅射类遗物（如「横扫：伤害溢出给下一段」）、「对群体 +X 点」的特质。

### 6.1 技能资源【建议】：骰能

主动技能消耗**骰能**。获取方式：**每投出一颗 1 点，获得 1 骰能**（另加每场战斗开场 +1）。
→ 运气差会自动积攒「翻盘资源」，天然的保底机制，也让 3d4（骰子多、出 1 概率高）和 1d12 拿资源的节奏不同。

### 6.2 技能树（每角色 3 条分支，每支 4~5 个节点，示例）

**铁卫「三棱」3d4**：骰子越多，每颗骰的加成越赚

- *匠心*：每颗攻击骰 +1 面（3d4 → 3d5）｜**本次骰子 +1（每颗）**——3 颗骰子吃到 +3
- *壁垒*：防御成功时护甲不磨损（每场 1 次）｜战斗中修复 2 级护甲（2 骰能）
- *增殖*：骰池 +1 颗 d2｜终极：攻击骰池 4d4

**战士「双子」2d6 · 暴怒**：✅ 已按背景重做，完整设定见 [characters/warrior.md](characters/warrior.md)

- **专属系统 · 怒气**：受伤、被格挡、护甲碎裂时积累怒气，怒气越高攻击越高、防御越低；满 10 进入**暴走**（3d6，但失去决策窗口，即「失控」）
- *克制之誓*（理智）：重投、守势、把怒气转化为护甲｜终极「赎罪」
- *焚怒*（暴怒）：开场怒气、卸甲换怒气、血怒｜终极「堕怒」
- *双子*（罗兰）：投出对子时触发追加攻击、穿透闪避
- **终极节点二选一，决定结局**

**赌徒「孤注」1d12**：放大方差，靠速度多投

- *爆骰*：投出最大值时再投一次并累加（可连爆）
- *豪赌*：主动技能「梭哈」：本次攻击 ×2，但没打穿防御就自损同等 HP
- *千术*：投出 1 时改为 12（每场 1 次）｜闪避成功后行动条 +25（连动）

**咒术师「蚀骨」d8+d4**：**减少对面骰子** + 控行动条

- *侵蚀*：主动技能：对面下一次投骰最大的那颗骰子 −2 面（1 骰能）
- *腐甲*：攻击命中时额外 −1 级护甲｜对无甲目标伤害 +2
- *诅咒*：给敌人挂「虚弱」（防 −1）/「无力」（攻 −1）/「迟缓」（速度 −3），复用特质系统

> 铁卫、赌徒、咒术师的技能树是 v0.1 的占位方案，**待按各自的罪和背景重写**（见 [To Do](TODO.md)）。节点数值待模拟后再定。

## 7. 特质

特质 = 长期被动修正，由**开局挑战选项 / 固定事件 / 诅咒 / 祭坛**给予。玩家和怪物共用同一套特质。

| 类型 | 特质 | 效果 | 来源举例 |
|---|---|---|---|
| 负面 | **体弱** | 防御点数 −1 | 开局挑战、被诅咒 |
| 负面 | **肌无力** | 攻击点数 −1 | 开局挑战、中毒事件 |
| 负面 | 迟钝 | 速度 −2 | 事件 |
| 负面 | 脆骨 | 防御失败时护甲额外 −1 级 | 恶魔契约代价 |
| 正面 | 坚韧 | 防御点数 +1 | 祭坛 |
| 正面 | 灵巧 | 闪避点数 +1 | 事件 |
| 正面 | 屠群者 | 对群体怪攻击 +1 | 固定事件 |
| 混合 | 嗜血 | 攻击 +2，防御 −2 | 恶魔契约 |

规则【建议】：同名特质**可叠层**（体弱×2 = 防 −2）；可以在神殿花钱净化负面特质；事件常给「正面 + 负面」的打包交易（参考杀戮尖塔的诅咒牌）。

## 11. 数值初稿 & 模拟结果

模拟器：`node sim/battle-sim.mjs [次数]`。只算基础规则（不含技能 / 遗物 / 怒气），ATB 行动条，护甲每场重置，无高打低，防御骰按 Q2 沿用本命骰形状。每组 20000 场，胜率与 HP 均为**无技能、1 级**的基线。

|---|---|---|---|---|
| 绿史莱姆 | 100% / 0.0 | 100% / 0.1 | 100% / 0.1 | 100% / 0.1 |

| 兽人蛮兵 | 99.3% / 21.5 | 95.9% / 29.9 | 91.8% / 25.5 | 87.7% / 36.0 |
| 骨龙 | 0% | 0% | 0% | 0% |

**结论（v0.3）**

1. **速度在 ATB 下非常值钱**：赌徒的速度从「先手 +1」变成了「约多 1/3 的行动次数」，打兽人的胜率从 v0.1 的 36% 升到 87%。速度是要重点控制的属性。
2. **四个角色的差距缩小了**：去掉高打低后兽人不再有 +1，胜率区间从 36%–96% 收窄到 88%–99%。铁卫仍然最稳，但已经不是碾压。
3. **防御骰改形状后（v0.3）**：赌徒护甲 1d6 → 1d8，打兽人胜率 87% → 92%；咒术师护甲 2d4 → d6+d2，等级不变，但那颗 d2 一碰就碎，变成最弱（88%）。咒术师的护甲或 HP 需要补强。
4. **战士的怒气还没进模拟**：裸装战士处于中游，怒气和暴走能把他推多高，是下一轮模拟的重点。
5. **护甲磨损让战斗前慢后快**：一场中等战斗双方各行动 5~8 次，节奏合适。
6. **群体 = 破甲器**：哥布林群单段只有 1d6，造成的伤害却和骷髅兵差不多。
7. **骨龙是成长检验点**：裸装 0% 胜率符合「首领要求成长」的预期。固定关卡下可以精确反推：先定「第 10 层时玩家应有的属性」，再调首领数值。

## 13. MVP 范围 & 技术建议

**MVP（可玩原型）**

- 1 个角色（战士 2d6）+ 怒气系统 + 完整技能树（三条分支，含终极二选一）
- 10 层手工地图（固定布局），6 种怪物，1 个首领
- 完整战斗状态机（ATB + 行动顺序条）+ 8 个遗物 + 4 个特质
- 概率版怪物手册

**技术**

- TypeScript；**战斗逻辑与渲染分离**（纯函数的 `combat-core`，渲染层可以选 Canvas / Phaser / React）
- 可设种子的随机数（seeded RNG），种子存进存档 → 能复现 bug、做战斗回放，并防止读档刷骰子
- ATB 用整数「刻」推进，不依赖帧率，逻辑层完全确定；表现层只负责把刻数插值成流动的行动条动画
- 遗物 / 特质 / 技能全部走**事件钩子 + 数据表**；关卡用 JSON / Tiled 地图编辑器配置
- 怪物手册的概率直接复用 `combat-core` 跑蒙特卡洛（Web Worker 里跑 2000 次，耗时不到 50ms）
