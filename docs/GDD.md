## 0. 一句话 & 设计支柱

**一句话**：经典魔塔的「爬层 + 钥匙门 + 资源规划」，把固定数值战斗换成**骰子对抗**，每个角色就是一套骰子，用技能和遗物去「驯服运气」；**HP、精力、魔力结晶**三种资源决定能走多远、变多强。

| 支柱 | 含义 | 落到设计上 |
|---|---|---|
| **骰子即角色** | 3d4、2d6、1d12……不同骰型 = 不同玩法 | 各角色**期望值接近（≈7）**，区别在**方差**和**操控骰子的方式** |
| **可计算的运气** | 魔塔的乐趣是「算」，骰子带来的是「赌」 | 怪物手册显示**胜率 / 期望掉血 / 最坏情况**；ATB 行动顺序**完全确定、提前可见** |
| **越打越破** | 护甲会磨损，战斗有节奏变化 | 前几次交锋拼防御，护甲碎后伤害陡增；群体怪专克护甲 |
| **每一环都能被改写** | 战斗流程每个阶段都有遗物钩子 | 统一的事件时序 + 修正顺序，保证遗物可组合、不打架 |
| **克制的复杂度** | 战斗规则只有一套，不再加新系统 | 角色差异只来自「本命骰 + 1 被动 + 1 主动」；资源压力放在地图探索（精力）上，不放在战斗里 |
| **罪即玩法** | 每个角色背负一宗罪，玩法由罪而来 | 被动、主动技能、专属遗物、结局都从角色的罪和故事推导 |

## 0.5 世界观与七宗罪（草案）

## 1. 核心循环（固定关卡的纯魔塔）

```
选角色(骰型) → 进入塔层 → 探索：开门/拿钥匙/捡宝石药水/遇事件（每走一步 −精力）
      ↑                         ↓
 商人/祭坛/营火 ← 击败怪物 → 魔力结晶 → 升级自身 / 交易 / 资源置换
      ↑                         ↓
   首领层 → 固定遗物奖励       特质（固定事件给予，好坏都有）
```

- **地图、怪物、道具、遗物、事件的位置全部固定**，由关卡策划手工摆放。玩家的乐趣在于**规划路线**：先开哪扇门、先打哪只怪、钥匙留给谁。
- **三种跨战斗资源**：HP（沿用魔塔「血量即货币」，但有上限）、**精力**（走路、交战、用技能都要花，见 10.1）、**魔力结晶**（唯一货币，见 10.2）。护甲每场结束后恢复满（见 2.2）。
- 随机来源只有**骰子**：战斗投骰，以及精力耗尽时的昏迷判定。关卡里不放随机掉落、随机事件，保证「同一张图，规划决定一切」。

### 1.1 固定关卡带来的设计要求【建议】

| 问题 | 方案 |
|---|---|
| **存档读档刷骰子**：固定地图下，玩家会读档重打一场烂运气的战斗 | ✅ 随机数种子写进存档：**读档后同样的操作会得到同样的骰子**，想改结果就必须改决策（换路线、换技能使用时机）。种子随每次投骰推进。另设**宽松模式**开关：开启后读档重新随机。已知局限：玩家仍可「读档看一遍骰子再读档」，种子方案挡不住，但必须改变决策才能改变结果，可以接受 |
| **一张图要适配四个角色** | ✅ 同一张塔。主路线按「裸装中位角色」设计；少量**角色专属格子**（同一位置，不同角色拿到不同的专属遗物 / 宝石），并为每个角色单独跑一遍数值验证 |
| **遗物不能三选一（那是 Roguelite 的做法）** | 遗物放在固定位置：首领掉落、隐藏房间、商人高价货；少数岔路做「二选一的门」，路线即选择 |
| **开局特质** | 改为**开局可选的挑战选项**：自愿带上负面特质，换取结算评分 / 称号（类似难度等级） |

## 2. 骰子基础规则

### 2.1 三种骰池

每个单位（玩家和怪物同规则）有三组骰：

| 骰池 | 作用 | 说明 |
|---|---|---|
| **攻击骰** | 攻击时投掷 | 角色的「本命骰」，决定角色身份 |
| **防御骰（护甲）** | 被攻击且未闪避时投掷 | 会**磨损**（见 2.2） |
| **闪避骰** | 被攻击时先投 | 通常很小（d2~d6），重甲怪可以没有 |

✅ **已定（Q2）：只有攻击骰是本命骰；防御骰另配，但沿用本命骰的「形状」；闪避骰统一用小骰（d2~d6）。**

- 为什么闪避不能用本命骰：2d6 攻击对 2d6 闪避，「A ≤ E」的概率是 55.6%，超过一半的攻击会被躲掉，战斗会拖长一倍。
- 形状沿用：多颗小骰的角色，护甲也是多颗小骰，一颗一颗地掉；单颗大骰的角色，护甲也是单颗大骰，要么挡住，要么挡不住。

| 角色 | 本命骰（攻击） | 防御骰（同形状） |
|---|---|---|
| 铁卫 | 3d4（三颗小骰） | 3d4 |
| 战士 | 2d6（两颗中骰） | d6+d4 |
| 赌徒 | 1d12（一颗大骰） | 1d8 |
| 咒术师 | d8+d4（一大一小） | d6+d2 |

### 2.2 护甲等级 & 磨损

把「2d6 防御失败 → 1d6+1d4」规则化：

- **护甲等级 = 所有防御骰的面数之和**。2d6 = 12 级，1d6+1d4 = 10 级。
- **每降 1 级：面数最小的那颗骰子 −1 面**（网页游戏可以有 d5、d3 这种实体不存在的骰子）。
- 骰子降到 d1 时**碎裂移除**。

```
2d6 → d6+d5 → d6+d4 → d6+d3 → d6+d2 → d6 → d5 → d4 → d3 → d2 → 无甲
 12     11      10      9       8      6    5    4    3    2
```

- 防御成功 −1 级，防御失败 −2 级。
- ✅ **已定：护甲只在单场战斗内磨损，战斗结束后恢复满**。怪物同理（不会出现「上次打残的怪」）。
- 【建议】同一套规则也用来**成长**：防御宝石 = 护甲上限 +1 级（给最小的骰子 +1 面）；攻击宝石同理。成长和磨损共用一套「面数阶梯」，玩家只需要学一次。

### 2.3 修正顺序（防止遗物互相打架）

每次投骰按以下顺序结算，**同一层内先攻击方、后防御方，同一方按获得顺序**：

1. **投骰前**：改骰池（加骰、换骰、「减少对面骰子」）
2. **投骰**
3. **骰面操作**：重投、锁定、翻面、把某颗骰改成指定值；全部完成后再判定**骰面条件**（如战士的「对子」），并加入因此追加的骰子
4. **加减值**：技能 +1、特质 ±1、遗物加值
5. **乘算**：暴击 ×2 等
6. **下限截断**：最终点数不低于 0

## 3. 战斗流程（状态机）

```
[战斗开场] ─→ [ATB 推进] ─→ [行动者攻击声明] ─→ [攻击投骰] ─→ [闪避判定]
                  ↑                                              │ 失败
                  │                                              ↓
           [战斗结束检查] ←── [受到伤害] ←──────────────── [防御判定]
                  │ 一方 HP ≤ 0
                  ↓
             [战斗结算]
```

| # | 阶段 | 做什么 | 遗物钩子（先攻击方 → 后防御方） |
|---|---|---|---|
| 1 | 战斗开场 | 初始化护甲、群体层数、行动条起始值 | `onBattleStart` |
| 2 | ATB 推进 | 推进行动条直到有人满条，决定行动者（见 3.1）；**玩家的主动技能在这里发动** | `onGaugeFull` / `onActionStart` |
| 3 | 攻击声明 | 确定段数（群体）、目标 | `onAttackDeclare` |
| 4 | 攻击投骰 | 按 2.3 结算攻击点数 **A** | `onAttackRoll` |
| 5 | 闪避判定 | 防御方投闪避 **E**；若 **A ≤ E** → 闪避，本段结束 | `onDodgeCheck` / `onDodged` |
| 6 | 防御判定 | 防御方投护甲 **D**；成功/失败，护甲 −1/−2 | `onDefenseCheck` / `onArmorBreak` |
| 7 | 受到伤害 | 扣 HP = max(0, A − D) | `onDamageTaken` / `onDamageDealt` |
| 8 | 结束检查 | 有一方 HP ≤ 0 → 结算；否则行动者行动条 −100，回到 2 | `onActionEnd` |
| 9 | 战斗结算 | 魔力结晶、掉落、特质触发；**护甲恢复满** | `onBattleEnd` / `onKill` |

### 3.1 ATB 行动条 ✅ 已定

**规则**

- 每个单位有一条行动条，**满值 100**，战斗开场为 0（技能 / 遗物可以给起始值，即「先手」）。
- 时间以「刻」推进，每刻行动条 **+速度**。
- 行动条 ≥ 100 → 该单位行动（一次完整攻击，含群体多段），行动后 **−100，保留溢出**。
- 同一刻多个单位满条：**溢出多者先 → 速度高者先 → 玩家优先**。
- 速度取值建议在 **8~14** 区间（平均 10）。速度比就是行动次数比：速度 14 对速度 10，我方每行动 5 次，对方行动 7 次，其中 2 次是连动。

**示例**（模拟器实际输出）：战士（速 10）vs 蝙蝠群（速 14），前 12 次行动：

```
敌 我 敌 我 敌 敌 我 敌 我 敌 敌 我
```

**为什么 ATB 不会破坏「可计算」**

- 速度和行动条**没有随机成分**，所以整场的行动顺序在开战前就能完全算出。
- 【建议】战斗界面顶部常驻**行动顺序条**（未来 8 次行动的头像队列，类似 FF10 的 CTB），怪物手册里也显示「敌我行动比」。
- 【建议】表现上行动条实时流动（满足「即时」感），但采用**等待模式**：玩家的决策窗口打开时，所有行动条暂停。

**ATB 带来的新设计空间**

| 类型 | 例子 |
|---|---|
| 推条 / 拉条 | 「震慑」：命中时目标行动条 −30；「疾风」：闪避成功后自身行动条 +20 |
| 先手 | 「伏击」：开场行动条 +50；蝙蝠这类高速怪开场就能连动 |
| 速度增减 | 特质「迟钝」速度 −2；咒术师的「减速诅咒」 |
| 持续时间 | 所有「持续 N 回合」统一改为「持续到**挂载者**的第 N 次行动结束」 |

> ⚠️ 模拟显示**速度在 ATB 下等于伤害乘数**：赌徒速度 12 时行动次数是速度 9 单位的约 1.3 倍。速度成长必须稀缺且昂贵（例如全塔只有 2~3 个速度宝石）。

### 3.2 玩家在战斗中的决策点【建议】

**交战确认**（撞上怪物时弹出）：显示概率手册（胜率 / 期望掉血 / 行动比）和本次交战的精力消耗，确认后才扣精力、进入战斗。

**战斗中**默认自动结算（可以 2×/4× 加速）。✅ 主动技能在**轮到自己行动时**发动：

- ✅ 交互上不打断自动战斗：战斗界面常驻**技能按钮**（手机上在右下角拇指区），随时可以按，按下后在**下一次轮到自己行动时**发动（按钮显示「已就绪」）。精力不足时按钮置灰。
- 发动时机在攻击投骰之前（第 2 步 `onActionStart`），✅ **不占用本次行动**，发动后照常攻击。
- 另外提供「每次轮到我时暂停」的选项，给想精确操作的玩家。

✅ **撤退（Q6）**：战斗中随时可以发起（行动条暂停后结算），首领战不能撤退。除了已经损失的 HP，没有额外惩罚；怪物的 HP 和护甲恢复满，随机种子继续往前走，下次再打骰子不同。相当于「花血换一次重投」，重新交战还要再付一次交战精力。撤退不掉落魔力结晶。如果测试中出现「打两下不行就跑」的滥用，再加「撤退扣 10% 魔力结晶」。

## 4. 判定公式（单段攻击）

```
A = 攻击骰结果 + 修正                     （特质、技能、遗物）
E = 闪避骰结果 + 修正
if A ≤ E:            → 闪避成功：无伤害，护甲不变（Q8）
D = 防御骰结果 + 修正
if A > D:            → 防御失败：HP −(A − D)，护甲 −2 级
else:                → 防御成功：无伤害，护甲 −1 级
```

- ✅ **Q7**：所有修正后点数截断为 0。0 点攻击必定被闪避（0 ≤ 任何 E，包括没有闪避骰时的 E = 0），显示为「无力的一击」。
- ✅ **Q8**：闪避成功**不磨损护甲**。三档反馈：闪避 = 什么都不丢；防御成功 = 掉 1 级护甲；防御失败 = 掉血并掉 2 级护甲。

**例**：战士（攻 2d6）打骷髅兵（闪 1d2，防 2d6）
1. 战士投出 9。骷髅兵闪避投出 2 → 9 > 2，闪避失败。
2. 骷髅兵防御投出 6 → 9 > 6，防御失败：骷髅兵 −3 HP，护甲 2d6 → d6+d4。
3. 下一次骷髅兵的防御期望从 7 降到 6，护甲越打越薄。

## 5. 群体机制

- 群体 N：每次攻击变成 **1 + N 段**，每一段**独立**投攻击骰，独立走闪避 / 防御 / 伤害。
- **群体对护甲是克星**：每一段都会磨掉 1~2 级护甲，所以群体怪单段骰子必须小（1d4~1d6），否则会碾压高护甲角色。
- ATB 下群体怪的总威胁 ≈ **段数 × 速度**。高速 + 群体（如蝙蝠群）要压低单段骰子或 HP。
- ✅ **群体随血量瓦解**（v0.9 采用）：群体 N 的怪每损失 1/(N+1) 的最大 HP，群体层数 −1。表现为「打散一群哥布林」，也让玩家的爆发更有价值。例：哥布林群（群体 2，HP 20）掉到 13 HP 时变成群体 1，掉到 6 HP 时变成单体。
- 【建议】给玩家留应对手段：群攻 / 溅射类遗物（如「横扫：伤害溢出给下一段」）、「对群体 +X 点」的特质。

### 6.1 技能结构 ✅ 已定

- **每个角色只有 1 个被动 + 1 个主动**，不设技能树，也没有怒气、骰能这类战斗内资源。

### 6.2 战士「双子」2d6 · 暴怒 ✅

| 类型 | 技能 | 效果 |
|---|---|---|
| 被动 | **罗兰之声** | ✅ 投出对子时，额外获得一颗与对子点数相同的骰子，**加入本次攻击**。例：投出 4、4 → 视为额外投出一颗点数为 4 的 d6，攻击 = 12。追加骰不连锁；每次攻击只触发一次 |
| 主动 | **卸甲** | ✅ 轮到自己行动时发动，消耗 10 精力，每场 1 次，不占用行动。直到战斗结束：无法闪避，失去**当前**护甲的一半，攻击骰 +1d6（2d6 → 3d6，出对子的概率从 17% 升到 44%） |

## 7. 特质

特质 = 长期被动修正，由**开局挑战选项 / 固定事件 / 诅咒 / 祭坛**给予。玩家和怪物共用同一套特质。

| 类型 | 特质 | 效果 | 来源举例 |
|---|---|---|---|
| 负面 | **体弱** | 防御点数 −1 | 开局挑战、被诅咒 |
| 负面 | **肌无力** | 攻击点数 −1 | 开局挑战、中毒事件 |
| 负面 | 迟钝 | 速度 −2 | 事件 |
| 负面 | 脆骨 | 防御失败时护甲额外 −1 级 | 恶魔契约代价 |
| 正面 | 坚韧 | 防御点数 +1 | 祭坛 |
| 正面 | 灵巧 | 闪避点数 +1 | 事件 |
| 正面 | 屠群者 | 对群体怪攻击 +1 | 固定事件 |
| 混合 | 嗜血 | 攻击 +2，防御 −2 | 恶魔契约 |

规则【建议】：同名特质**可叠层**（体弱×2 = 防 −2）；可以在神殿花魔力结晶净化负面特质；事件常给「正面 + 负面」的打包交易（参考杀戮尖塔的诅咒牌）。

### 10.1 精力系统 ✅ 已定（数值为初稿）

精力是**探索资源**，和 HP 一起决定能走多远。它不改变战斗规则，只决定「这一架、这条路、这个技能值不值」。

**消耗**

| 来源 | 消耗（初稿） | 说明 |
|---|---|---|
| 移动 | 每格 −1 | 走回头路、回低层商店都要花精力，路线规划多了一个维度 |
| 进入战斗 | −3 | 交战确认后扣除；撤退后重新交战要再付 |
| 主动技能 | 按技能（战士「卸甲」−10） | |
| 事件 | 按事件 | 如「迷雾走廊」−5、「攀爬断崖」−8（换取捷径） |
| 怪物技能 | 按怪物 | 如「疲惫之触」：打穿防御时额外 −2 精力 |

**恢复：营火**

- 塔内固定位置设有营火。✅ 每次「休息」恢复 **40 精力** + **30% HP 上限**的 HP。
- ⚠️ 一堆营火 3 次休息最多恢复 90% HP，是全塔最主要的回血来源之一。营火数量和柴火次数要比原先更省，血瓶也要相应减少，否则 HP 压力会消失。
- 每堆营火有**柴火次数**（初稿 3 次），用完熄灭，地图上显示剩余次数。
- 遗物可以提高恢复量（旅人铺盖）或补充柴火（干柴束）。

**HP 上限**：因为营火按比例回血，HP 需要上限（经典魔塔没有）。开局 HP = 上限，上限通过祭坛升级提高。好处是多了一层规划：血瓶在满血时捡会浪费，玩家要算好什么时候去拿。

**耗尽：昏迷判定**

精力降到 0 时立即昏迷，投 **1d12**：

| 点数 | 结果 | 精力恢复（初稿） | 精力上限 |
|---|---|---|---|
| 1 | **大失败**：昏睡中遇到魔物，没能醒来 → **死亡** | — | — |
| 2–4 | 遇到魔物，惊醒逃开（✅ 只是剧情描述，不触发战斗） | +10 | −5 |
| 5–11 | 安稳睡了一觉 | 点数 × 5（25～55） | −5 |
| 12 | **大成功**：睡得很好 | +60 | 不减 |

- 死亡概率每次 1/12 ≈ 8.3%：精力见底是真正的危险，不是小惩罚。
- 【建议】**大失败 / 大成功只看骰面原始点数**；遗物的加值只影响恢复量，不能把 1 点改成 2 点（守夜铃）。
- 【建议】**战斗中不会昏迷**：战斗中精力最低降到 0，战斗结束后如果精力为 0，立刻进行昏迷判定。
- 【建议】**精力上限保底 30**：防止多次昏迷后上限越扣越低，陷入「走几步就昏」的死循环。
- 昏迷判定也走存档里的随机种子（Q9）：读档后同样的操作会得到同样的结果。

**关卡设计约束**

- 用模拟或手算验证：每层最优路线的精力消耗 + 交战次数，在营火供给范围内有明显余量。
- 营火的位置和柴火次数是关卡设计的核心旋钮：放在岔路口逼玩家选路线，放在首领前给玩家喘息。
- 楼层传送（魔塔原版的「楼层飞行器」）也收精力，例如每跨一层 −5，避免回头路免费。

### 10.2 魔力结晶 ✅ 已定（数值为初稿）

**魔力结晶是唯一的货币，取代经典魔塔的金币和经验。** 每一颗结晶都要在「变强」和「换资源」之间二选一，经典魔塔里「金币买钥匙还是买攻防」的抉择被集中到了一个预算里。

**获取**：击杀怪物掉落固定数量（固定关卡，掉落量写在怪物手册里）；撤退不掉落。少量来自隐藏房间和事件。

| 怪物 | 掉落（初稿） |
|---|---|
| 绿史莱姆 | 2 |
| 蝙蝠群 | 3 |
| 骷髅兵 | 5 |
| 哥布林群 | 6 |
| 兽人蛮兵 | 10 |
| 骸骨队长（原型第 3 层首领） | 40 |

**三种用途**

| 用途 | 在哪 | 内容（初稿） |
|---|---|---|
| **升级自身** | 祭坛 | 每次选一项：攻击骰阶 +1 / 防御骰阶 +1 / HP 上限 +10 / 精力上限 +10。价格逐次上涨：第 n 次花费 = 20 + 10 × (n − 1)。速度不能在祭坛买，只能靠速度宝石 |
| **商人交易** | 商人（固定位置、固定货架） | 黄钥匙 10、蓝钥匙 30、小血瓶 15、柴火 20（给营火 +1 次）、遗物 50～120 |
| **资源置换** | 置换点（固定位置、固定汇率） | 例：「结晶泉」10 结晶 → 25 精力；「钥匙匠」3 把黄钥匙 → 1 把蓝钥匙；「回收商」多余钥匙半价换回结晶；「血契祭坛」10 HP → 5 结晶 |

**设计要点**

- 祭坛价格递增，防止「全部拿去升级」成为唯一答案；置换点的汇率故意偏亏，它是**救急手段**，不是赚钱手段。
- 「血契祭坛」把 HP 也变成可兑换的资源，配合营火回 30% HP，玩家可以规划「先卖血升级，再去营火补」的路线。
- 骰匠（改骰型）和神殿（净化特质）也收结晶。

**首领战**（按预期成长：攻 d8+d7、防 2d6、HP 上限 60）

| 战前 HP | 不卸甲 | 护甲磨损过半后卸甲 |
|---|---|---|
| 60 | 60% | 91% |
| 45 | 30% | 64% |
| 35 | 14% | 37% |

**自动游玩**（400 局，「中等水平」机器人：最近目标优先、只打胜率 ≥ 95% 的怪、护甲磨损过半后卸甲）

| 精力上限 | 通关率 | 平均昏迷 | 主要失败原因 |
|---|---|---|---|
| 100 | 71% | 2.4 次 | 昏迷死亡 17%、首领 9% |
| **120（采用）** | **70%** | **1.3 次** | 首领 20%、昏迷死亡 9% |
| 150 | 66% | 1.0 次 | 首领 22%、昏迷死亡 12% |

**结论**

1. **精力上限 100 太紧**：机器人平均每局昏迷 2.4 次，每次 1/12 的死亡率叠起来，17% 的局死在昏迷上。调到 120 后昏迷降到 1.3 次，失败主要来自首领战，这才是想要的压力来源。
2. **卸甲的时机比用不用更重要**：等护甲磨损过半再卸，对所有怪都不亏；首领战里会不会用卸甲，胜率差 30 个百分点。这是原型里最重要的技巧。
3. **首领要求满状态挑战**：满血 91%、45 血只有 64%，所以首领前放了营火和祭坛，让玩家做战前准备。
4. **群体瓦解让群体怪更好打**：哥布林群因此改成 1d8 攻击、20 HP，平均掉血保持在 7 左右。
5. **地图上的血瓶会挡住自动寻路**：机器人一开始卡住，就是因为满血时不愿意喝挡路的血瓶。这和经典魔塔一样，是规划的一部分；但玩家需要在界面上清楚地看到「这条路要先喝掉血瓶」。

## 13. MVP 范围 & 技术建议

**原型 v0.1（已完成，可玩）** 🚧

- 战士（被动「罗兰之声」+ 主动「卸甲」）、**3 层**手工地图、6 种怪物、首领「骸骨队长」
- ATB 战斗与行动顺序条、常驻技能按钮、撤退、战斗加速、「每次轮到我时暂停」
- 精力、营火、昏迷判定；魔力结晶、祭坛、商人、置换点；战士专属事件「磨坊的余烬」
- 交战确认 / 怪物手册的概率预测（不卸甲 vs 护甲磨损过半后卸甲）
- 存档（IndexedDB + 存档码 + 切后台自动存档）、PWA 离线、简体中文 / 英文
- 原型阶段的取舍：战斗界面用 DOM 实现（地图用 Phaser）；地图用程序绘制的占位图形；遗物和特质只做了「坚韧」一个

**MVP 目标（下一步）**

- 1 个角色（战士 2d6）+ 被动「罗兰之声」+ 主动「卸甲」
- 精力系统：移动消耗、营火（回精力 + 30% HP）、昏迷判定
- 魔力结晶：怪物掉落、祭坛升级、1 个商人、2 个置换点
- 10 层手工地图（固定布局），6 种怪物，1 个首领
- 完整战斗状态机（ATB + 行动顺序条）+ 8 个遗物 + 4 个特质
- 概率版怪物手册

**平台与技术** ✅ HTML5 网页游戏，同时适配手机端。完整方案见 [tech/platform.md](tech/platform.md)，要点：

- **竖屏手机优先**，平板 / 电脑横屏同样完整；经典 11 × 11 地图正好占满手机屏宽；可「添加到主屏幕」并离线游玩（PWA）
- **点击格子自动寻路 + 二次确认**，路线预览显示步数和精力消耗；精力不够走完时路线变红，标出会昏迷的位置
- ✅ 技术栈：TypeScript + Vite；Phaser 3 负责地图和战斗演出，DOM 叠层负责商人、祭坛、手册等文字界面
- ✅ **国内 + 海外同时发布**：同一次构建，国内走备案域名 + 国内 CDN，海外走 Cloudflare Pages / itch.io 等；首发简体中文 + 英文，所有文本从第一天起放进语言表
- ✅ **完全免费**：无广告、无内购、无账号、无服务器，存档只在玩家本地；发布渠道以自有网站 + itch.io 为主
- **规则与渲染分离**：纯 TS 的 `combat-core`，游戏、概率手册（Web Worker）、数值模拟器、自动化测试共用同一份规则
- 可设种子的随机数（seeded RNG），种子存进存档 → 能复现 bug、做战斗回放，并防止读档刷骰子；切到后台时自动存档
- ATB 用整数「刻」推进，不依赖帧率，逻辑层完全确定；表现层只负责把刻数插值成流动的行动条动画
- 遗物 / 特质 / 技能全部走**事件钩子 + 数据表**；关卡用 JSON / Tiled 地图编辑器配置
- 性能预算：首屏 < 5 MB，中低端手机 60 帧，概率手册在手机上 < 100 ms
