# 平台与移动端适配 · 技术方案 v0.2

> 所属：[游戏设计文档](../GDD.md) 第 13 节｜✅ 已定：**HTML5 网页游戏发布，同时适配手机端；技术栈按第 2 节采用；国内与海外同时发布**

---

## 1. 目标

| 项目 | 目标 |
|---|---|
| 平台 | 浏览器直接打开即玩，不需要安装；可「添加到主屏幕」（PWA） |
| 设备 | 手机竖屏为**第一优先**；平板和电脑横屏同样完整可玩 |
| 地区与语言 | 国内 + 海外同时发布；简体中文 + 英文（见第 7 节） |
| 浏览器 | iOS Safari、Android Chrome、微信内置浏览器、桌面 Chrome / Edge / Firefox / Safari 的最近两个大版本 |
| 首次加载 | 首屏资源 < 5 MB，4G 网络下 5 秒内可以开始游戏 |
| 性能 | 中低端手机（约 4 年前的机型）稳定 60 帧；战斗加速时不掉帧 |
| 离线 | 加载过一次后可离线游玩（Service Worker 缓存） |

---

## 2. 技术栈 ✅ 已采用

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 / 构建 | TypeScript + Vite | 类型安全，适合数据表驱动的规则；Vite 打包快，产物是纯静态文件，任何静态托管都能发布 |
| 规则核心 | 纯 TS 的 `combat-core` / `tower-core`，无渲染依赖 | 游戏、概率手册（Web Worker）、数值模拟器、自动化测试共用同一份规则 |
| 地图 & 战斗演出 | Phaser 3（Canvas / WebGL 自动切换） | 自带缩放管理、触屏输入、补间动画、音频解锁，HTML5 小游戏生态成熟 |
| 文字类界面 | DOM 叠层（商人、祭坛、手册、对话、设置） | 中文文本清晰、自动换行、易做响应式布局；比在 Canvas 里排版省事得多 |
| 存档 | IndexedDB（主）+ localStorage（设置） | 存档含随机种子（Q9）；提供「导出 / 导入存档码」，换设备也能继续 |
| 离线 & 安装 | PWA：manifest + Service Worker | 可添加到主屏幕，全屏启动 |

> 备选：如果更想要轻量，可以用 PixiJS 只负责渲染，其余自己写。Phaser 的优势是「输入、缩放、音频、场景」开箱即用，对移动端适配省心。

## 3. 屏幕布局

### 3.1 地图：经典 11 × 11

- 沿用经典魔塔的 **11 × 11** 格地图。
- 竖屏手机（宽 360～430 CSS 像素）：每格约 32～38 像素，地图正好占满屏幕宽度。
- 美术建议用**像素风**，按整数倍缩放（`image-rendering: pixelated`），任何分辨率下都清晰。

### 3.2 竖屏（手机）

```
┌─────────────────────────┐
│ ❤ 42/50  ⚡ 63/100  💎 27 │  ← 资源栏：HP / 精力 / 魔力结晶
│ 🔑 黄2 蓝1 红0   第 3 层   │
├─────────────────────────┤
│                         │
│      11 × 11 地图         │  ← 点击格子 = 寻路
│                         │
├─────────────────────────┤
│ 路线预览：12 步 · ⚡ −12    │  ← 寻路时显示精力消耗
├─────────────────────────┤
│   [手册] [背包] [遗物]      │
│                         │
│        ▲                │  ← 方向键（可在设置里隐藏）
│      ◀   ▶      [菜单]   │
│        ▼                │
└─────────────────────────┘
```

### 3.3 横屏（平板 / 电脑）

```
┌──────────────────────────────┬─────────────────┐
│                              │ 角色面板          │
│                              │ HP / 精力 / 结晶    │
│        11 × 11 地图            │ 骰子 / 特质 / 遗物  │
│                              ├─────────────────┤
│                              │ 怪物手册（悬停即看）  │
└──────────────────────────────┴─────────────────┘
```

### 3.4 战斗界面（竖屏）

```
┌─────────────────────────┐
│ 行动顺序：我 敌 敌 我 敌 我…  │  ← ATB 顺序条（未来 8 次行动）
├─────────────────────────┤
│   兽人蛮兵  HP ████░ 18     │
│   护甲 [d6][d4]  行动条 ▓▓░  │
│                         │
│        🎲 🎲 🎲          │  ← 投骰演出区
│                         │
│   凯恩     HP ███░░ 31     │
│   护甲 [d5]  行动条 ▓░░░    │
├─────────────────────────┤
│ [撤退]   [1× 2× 4×]  [卸甲] │  ← 常驻技能按钮放在右下（拇指区）
│                  ⚡10 已就绪 │
└─────────────────────────┘
```

- **技能按钮常驻右下角**（✅ 已定）：按下后显示「已就绪」，下次轮到自己时发动；精力不足时置灰。
- 撤退在左下，与技能按钮分开，防止误触。

## 4. 操作

| 操作 | 手机 | 电脑 |
|---|---|---|
| 移动 | **点击目标格自动寻路**；方向键逐格走 | 方向键 / WASD；鼠标点击寻路 |
| 寻路确认 | 第一次点击显示路线和精力消耗，**再点一次才出发** | 同左，或按住 Shift 直接出发 |
| 查看怪物 | 长按怪物 → 概率手册 | 鼠标悬停 |
| 战斗技能 | 点击常驻按钮 | 点击按钮或按空格 |
| 战斗加速 | 点击加速按钮 | 按 F |

**寻路规则**

- 自动寻路**不会穿过**怪物、门、事件、道具：路线停在它们前一格，由玩家自己决定是否交战或开门。
- 路线预览总是显示「步数 · 精力消耗」。精力不够走完时，路线变红并标出会昏迷的位置。这是精力系统在 UI 上最重要的配合。

## 5. 移动端必做清单

| 问题 | 处理 |
|---|---|
| 刘海屏 / 底部手势条 | 布局使用 `env(safe-area-inset-*)` 留出安全区 |
| 双击缩放、下拉刷新 | `touch-action: none`（地图区域）、`overscroll-behavior: none` |
| 视口 | `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` |
| 触控目标 | 按钮至少 44 × 44 像素；地图格较小，所以移动以「点击寻路 + 二次确认」为主 |
| iOS 音频 | 第一次触摸时解锁 AudioContext（Phaser 自带） |
| 切到后台 | `visibilitychange` 时**自动存档**，并暂停战斗和 ATB；手机浏览器随时可能回收后台标签页 |
| 横竖屏切换 | 监听尺寸变化，在两套布局之间切换，不重开游戏 |
| 中文字体 | 使用系统字体，不打包完整中文字体（动辄 5～10 MB）；如需美术字，只给标题做子集化 |
| 微信内置浏览器 | 单独测试（内核和 Safari / Chrome 有差异）；分享卡片标题和图标 |
| 低端机 | 「减少动画」开关：跳过投骰动画，直接显示结果 |

## 6. 性能预算

| 项目 | 预算 |
|---|---|
| 首屏包（JS + 必要图片 + 音频） | < 5 MB；后续楼层资源按需加载 |
| JS 主包 | < 500 KB（gzip 后） |
| 概率手册计算 | Web Worker 中跑 1000～2000 场模拟，手机上 < 100 ms；结果按「角色状态 + 怪物」缓存 |
| 战斗演出 | 4× 加速时每次行动 < 200 ms；规则计算与动画分离，动画可以跳过 |
| 存档 | 每次存档 < 50 KB |

## 7. 发布 ✅ 国内 + 海外同时发布

### 7.1 一套代码，两套部署

| | 国内 | 海外 |
|---|---|---|
| 托管 | 国内云的对象存储 + CDN（如阿里云 OSS、腾讯云 COS） | Cloudflare Pages / Vercel / GitHub Pages |
| 域名 | 需要 **ICP 备案**（国内服务器 / CDN 的前提） | 无需备案 |
| 平台 | TapTap、4399 等网页游戏平台；微信内置浏览器打开 | itch.io、CrazyGames、Poki 等 |
| 默认语言 | 简体中文 | 英文 |

- 构建产物是**纯静态文件**，同一次构建分别部署到两个区域，只在配置上区分（默认语言、统计服务、分享方式）。
- 存档码两边通用，玩家换区域也能继续玩。

### 7.2 多语言（海外发布的前提）

- **从第一行代码开始做本地化**：所有界面文字、技能 / 遗物 / 特质 / 事件 / 剧情文本都放在语言表里，用 key 引用，代码中不写死任何中文。
- 首发语言：**简体中文、英文**。之后可加繁体中文、日文（魔塔在日本也有受众）。
- 默认按浏览器语言选择，设置里可以手动切换。
- 排版：英文通常比中文长 30%～60%，按钮和面板要按英文长度留出空间，并用英文版做手机竖屏测试。
- 字体：中英文都用系统字体栈，不打包字库。
- 角色名、技能名需要正式英文译名（如 Kane Ashoath、Roland's Voice、Unarmor），统一记在术语表里。

### 7.3 国内发布：合规风险（需要专业确认）

> ⚠️ 以下是需要提前了解的风险点，不是法律意见。具体要求请向发行平台或专业人士确认。

- **版号**：在国内运营网络游戏原则上需要取得版号；在平台上架和做商业化（内购、广告）时，平台通常会要求提供版号。是否需要、何时申请，取决于商业模式和发行渠道。
- **实名认证与防沉迷**：取得版号的网络游戏需要接入实名认证和未成年人防沉迷。
- **内容审核**：送审时，骷髅、血腥等表现常被要求修改。本作的「骷髅兵」「骨龙」和战士背景中的屠杀情节，【建议】美术上预留**可替换的资源版本**（例如骷髅换成石像或亡灵铠甲、血色调整），国内和海外分别打包。
- **个人信息**：如果接入账号、统计、云存档，要遵守《个人信息保护法》，提供隐私政策。

### 7.4 海外发布

- 如果在欧盟地区使用统计或 Cookie，要遵守 GDPR（Cookie 同意提示、隐私政策）。
- 网页游戏平台（Poki、CrazyGames 等）有各自的 SDK、广告与包体要求，按平台单独接入，放在适配层，不碰规则核心。

### 7.5 后续渠道

- 微信小游戏、App 商店是后续选项：规则核心是纯 TS，可以复用；渲染层需要适配。

## 8. 开发顺序【建议】

1. 搭建 TypeScript + Vite 工程，接入 PWA 和多语言框架（语言表 + key）。
2. 把 `sim/battle-sim.mjs` 移植为 `combat-core`，并用单元测试锁住规则（护甲磨损、对子、卸甲、ATB 顺序）。
3. 竖屏布局 + 11 × 11 地图 + 点击寻路 + 精力预览。
4. 战斗界面：ATB 顺序条、投骰演出、常驻技能按钮。
5. 商人、祭坛、置换点、营火的 DOM 界面。
6. 存档（IndexedDB + 种子）与切后台自动存档。
7. 横屏布局。
8. 真机测试：iPhone Safari、安卓 Chrome、微信内置浏览器；中英文各测一遍。
9. 两套部署：国内（备案域名 + 国内 CDN）与海外（Cloudflare Pages 等）。
